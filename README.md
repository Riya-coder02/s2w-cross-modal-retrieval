Designers and developers often need to find app screens that match a description ("login page with social sign-in buttons"), and the reverse: describe a screen they already have. This project builds and compares systems that retrieve **the right screenshot for a text summary (text→screen)** and **the right summary for a screenshot (screen→text)**.

## Data

[RICO-Screen2Words](https://huggingface.co/datasets/rootsautomation/RICO-Screen2Words) (Wang et al., 2021; Deka et al., 2017) contains **22,417 Android screenshots** from 6,269 apps in 28 categories, each with **five human-written summaries** (112,085 in total).

- **Licence:** annotations are CC BY 4.0. The screenshots come from RICO and may contain third-party copyrighted material, so **this repository does not contain or redistribute any images, features or dataset files**. The notebook downloads the data directly from Hugging Face.
- **Quality issues handled:** 979 duplicate captions within a screen are removed, a malformed category label is relabelled, unreadable images are dropped, and near-duplicate screens across apps are kept out of the test set by the split (see below).

## Methods

All models use **frozen** pretrained encoders. For screens, **ResNet-50** and **ViT-B/16** (both ImageNet) are compared; for captions, **BERT-base** with mean pooling and with the [CLS] token. The combination with the best *validation* recall is used for all models.

| Method | Fusion type | Idea |
|---|---|---|
| Ridge regression | baseline | Linear map from caption features to image features, ranked by cosine similarity |
| Early fusion MLP | joint representation | Concatenate projected image and caption features; an MLP scores every pair |
| Contrastive dual encoder | coordinated representation | Separate projections into a shared space, symmetric InfoNCE, all captions of a screen as positives |
| Contrastive + re-ranking | hybrid | Contrastive model retrieves the top K, early fusion re-scores them |
| CLIP ViT-B/32 zero-shot | external reference only | Large pretrained model, not a main technique |

**Leakage-aware split.** An app-level split still left test screens with near-identical twins in training (screens built from the same templates in different apps). Apps are therefore linked whenever any of their screens have ResNet-50 cosine similarity above 0.95, and each connected group stays inside one split (80/10/10).

**Evaluation.**
- Recall@1/5/10, MRR and median rank in both directions, plus a relaxed Recall@10 that accepts identical generic captions.
- Mean ± sd over 3 seeds and 95% cluster-bootstrap confidence intervals.
- A train-vs-validation gap with a regularisation ablation to assess overfitting.
- Macro-averaged per-category recall for the bias assessment.
- Query cost against gallery size.
- A sensitivity analysis that rebuilds the split at a stricter near-duplicate threshold (0.98) to check that the conclusions hold.

## Repository structure

```
s2w_retrieval.ipynb     experiment notebook: runs the pipeline, prints all tables, draws all figures (saved with outputs)
s2w/                    Python package with all reusable code
  data.py               loading, caption cleaning, caption index
  features.py           frozen ResNet-50 / ViT-B/16 / BERT feature extraction, image quality stats
  splits.py             near-duplicate detection, app grouping, leakage-aware split, leakage report
  tensors.py            per-split tensors, train-only standardisation, positive-pair masks
  models.py             ridge, early-fusion MLP, contrastive dual encoder, multi-positive InfoNCE
  training.py           batching, false-negative masking, training loop with early stopping
  evaluation.py         Recall@K / MRR / median rank (strict and relaxed), re-ranking, cluster bootstrap
  utils.py              seeding, timing, Reporter (writes results, tables, figures)
tests/test_core.py      unit tests for metrics, losses, models and splitting (`pytest -q`)
requirements.txt        Python dependencies (only needed outside Colab)
results/
  results.json          every reported number
  RESULTS.md            main tables in Markdown
  tables/*.csv          all tables (Table 1–14)
  figures/*.png         all figures (Figure 1–8)
```
These folders are created when the notebook runs but never committed: `private_outputs/` (figures that contain screenshots: the privacy review and qualitative examples) and `cache/` (extracted features).

## How to reproduce

**Google Colab (recommended, free T4 GPU)**
1. Click the *Open in Colab* badge above. The first cell clones this repository to get the `s2w` package (set `REPO_URL` there if you forked it).
2. *Runtime → Change runtime type → T4 GPU.*
3. *Runtime → Run all.* Allow Google Drive access when asked: extracted features are cached in `MyDrive/s2w_cache`, so a disconnect does not repeat the extraction.
4. The first run takes about 75–100 minutes: download about 5 min, ResNet-50 + BERT extraction about 12 min, ViT-B/16 extraction about 12 min, training and evaluation the rest. With cached features a rerun takes about 30–40 minutes. At the end, `results.zip` downloads automatically.

**Privacy exclusions:** Section 4 shows 80 random screens. The `screenId` of every screen showing readable personal information is listed in `EXCLUDE_SCREEN_IDS` in the configuration cell. These screens are removed after the split is formed, so changing the list does not reshuffle the split.

**Locally (GPU recommended):** `pip install -r requirements.txt`, then run the notebook with Jupyter from the repository root. Unit tests: `pip install pytest && pytest -q`.

Seeds are fixed (`SEED = 42` for the split, `SEEDS = [0, 1, 2]` for training). Small differences between GPU types are possible.

## Ethics and bias

- No images, extracted features or personal data are committed. Figures that contain screenshots stay in the git-ignored `private_outputs/`.
- Screens with readable personal information are excluded and counted. Login, payment and messaging screens are counted and never shown.
- The data are English-only Android apps from about 2017, so the results may not generalise to iOS, other languages or current design styles. Category imbalance is assessed with macro-averaged recall and bootstrap intervals.
